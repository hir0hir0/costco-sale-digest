# レビュー観点チェックリスト（costco-sale-digest）

> ここは**監査レーン**のチェックリスト（欠陥の発見）。
> 機能・見せ方の**提案**は `/propose` の担当で、チェックリストを持たない（持つと発想が縮むため）。

各エージェントは自分の担当セクションを網羅すること。人間が手で回すときのチェックリストとしても使える。

---

## A. タスク遂行UX（ux-task-reviewer）
- [ ] personas.md の T1〜T9 がそれぞれ何クリック・何スクロールで完遂するか実測したか
- [ ] トップ画面を3秒見て「このサイトが何を提供するか」が分かるか
- [ ] 「今週の目玉」と「価格履歴」の導線が競合していないか
- [ ] データの出所（メルマガ／レシート）が訪問者に伝わるか
- [ ] 空状態（該当商品なし・履歴1件のみ・レシート未取込）の表示が用意されているか
- [ ] 検索に失敗したとき、次に何をすればよいか示されるか

## B. 情報設計・一覧性（ia-reviewer）
- [ ] 一覧のデフォルト並び順は何か。P1 の関心（値引き率／新着）と合っているか
- [ ] フィルタ軸は足りているか（カテゴリ／割引種別／期間／値下げ幅／データソース）
- [ ] 検索は表記ゆれに耐えるか（カタカナ／英字／ブランド名／商品番号／レシート略称）
- [ ] 価格の隣に**比較の基準**（前回価格・平均・最安）が出ているか
- [ ] 単位価格（円/100g、円/個）が併記されているか
- [ ] 値下げ額と値下げ率のどちらを主表示にしているか。根拠があるか
- [ ] **T9**: 告知価格と実売価格が画面上で視覚的に区別されているか
- [ ] 1画面あたりの件数がスマホで現実的か

## C. 統合データの整合性（data-integrity-reviewer）★最重要
- [ ] 商品の同定キーは何か。商品名の文字列一致に依存していないか
- [ ] コストコの**商品番号（item number）**を保持しているか
- [ ] メルマガ由来とレシート由来を**同一商品として紐付ける規則**は何か。誤結合をどう防ぐか
- [ ] **告知価格と実売価格を、同じ時系列・同じグラフに混ぜていないか**
- [ ] 同一商品の名称変更（リニューアル・年号違い）で履歴が分断されないか
- [ ] **内容量の変更**を検知・記録しているか（実質値上げの見逃しは致命的）
- [ ] 税込／税抜が混在していないか。保存時と表示時で一貫しているか
- [ ] メルマガ価格は全国共通、レシート価格は特定店舗の値。この非対称を「同じ商品の価格」として一般化していないか
- [ ] 価格の「有効期間」を持っているか。点データと期間データが混ざっていないか
- [ ] 割引種別（即時値引き／クーポン／メンバー限定）が区別されているか
- [ ] 同じ商品が同日に複数レコードで入った場合の扱いが決まっているか
- [ ] 欠測期間をグラフ上で「価格変化なし」と誤読させていないか
- [ ] レシートは自分の購入分のみ＝**カバレッジが偏る**。この偏りを平均値や「最安値」の算出に持ち込んでいないか
- [ ] 「過去最安値」「平均価格」が、どの母集団（メルマガのみ／レシートのみ／両方）から算出されたか画面で分かるか
- [ ] 過去データの遡及修正で履歴が上書き消失しないか
- [ ] 通貨・桁区切り・端数処理が全画面で一致しているか

## D. レシート取り込みパイプライン（receipt-pipeline-reviewer）★新設
- [ ] `CLAUDE.md` に書かれた取り込み手順と、実装・実データが一致しているか
- [ ] **合計の検算**は実装として自動実行されるか、手順書上の口約束か
- [ ] 検算が合わないとき、取り込みは**中断されるか**。警告だけで通っていないか
- [ ] レシートの読み取り誤り（桁落ち、0とO、Iと1、小数点）を検出する仕組みがあるか
- [ ] 数量×単価の行、値引き行、クーポン行、税行、袋代等を正しく分類しているか
- [ ] レシートの**英字略称**を正式な商品名に対応付ける辞書があるか。無い場合どう名寄せしているか
- [ ] 名寄せに**失敗した行**が捨てられていないか。未紐付けリストとして残るか（T11）
- [ ] 同じレシートを2回取り込んだときに重複しないか（冪等性）
- [ ] レシート原本（画像/テキスト）を保存しているか。後から再処理できるか
- [ ] **個人情報**：会員番号、レジ番号、支払方法、カード下4桁、購入者名が保存データや公開ファイルに混入していないか
- [ ] 取り込み結果のサマリ（件数・検算結果・未紐付け数）が運用者に提示されるか（T10）

## E. 運用継続性（ops-resilience-reviewer）
- [ ] メルマガのHTML構造が変わったとき、パースは**静かに失敗**しないか（0件でも成功扱いになっていないか）
- [ ] 取り込み結果の件数・失敗を記録／通知する仕組みがあるか
- [ ] 生のメルマガ原本を保存しているか（後からパースし直せるか）
- [ ] データの保存形式は、手で直せる／バックアップできる形か
- [ ] 更新が止まったことに、訪問者と運用者の双方が気づけるか
- [ ] 数年運用したときのデータ量とページ表示速度の見込み
- [ ] リポジトリに秘密情報（メール認証情報、APIキー）がコミットされていないか

## F. ドキュメント乖離（docs-drift-reviewer）★新設
- [ ] `CLAUDE.md` の記述が現在のコードと一致しているか（ファイル構成、コマンド、データ形式）
- [ ] `CLAUDE.md` の「検算必須」等のルールが、コードで強制されているか、人間の記憶頼みか
- [ ] 過去に踏んだ落とし穴が `CLAUDE.md` に反映され続けているか
- [ ] README と CLAUDE.md で矛盾していないか
- [ ] 新しいセッションの Claude が CLAUDE.md だけで作業を再現できるか（欠けている前提はないか）

## G. モバイル・アクセシビリティ（mobile-a11y-reviewer）
- [ ] 375px幅で横スクロールが発生しないか（特に表とグラフ）
- [ ] 店頭の明るさを想定したコントラスト比（4.5:1以上）
- [ ] タップ領域が44px以上か
- [ ] 価格グラフが色だけに依存せず値を読めるか
- [ ] 表がスマホで潰れていないか（カード表示への切替）
- [ ] 価格の文字サイズが本文より大きいか

## H. 法務・公開リスク（legal-risk-reviewer）

> 判定基準は personas.md の「**公開ポリシー**」表。方針は「公開する。ただし出さずに済むものは出さない」。
- [ ] メルマガ本文をそのまま転載していないか（事実である価格・商品名の抽出に留めているか）
- [ ] 商品画像・ロゴを転載していないか
- [ ] 「コストコ」商標の使い方。公式と誤認される表記・デザインでないか
- [ ] 非公式サイトである旨の明示（免責）があるか
- [ ] **レシート由来データの公開**：公開ポリシー表の「粒度を落として公開」が守られているか（購入日は月単位／店舗と数量は出さない）
- [ ] 「公開しない」区分（レシート原本・会員番号・レジ番号・支払方法・カード下4桁）が1つでも出ていないか
- [ ] GitHubリポジトリが public の場合、生データ・レシート原本もろとも公開されていないか
- [ ] 取得元サイトの利用規約・robots.txt に反する取得をしていないか
- [ ] 公開ポリシーからの逸脱があった場合、**サイトを非公開にせよ**ではなく**その項目を落とせ**という形で修正案を書いているか

## I. 競合比較（competitive-reviewer）

> 現時点は自分用フェーズ。ここの指摘は原則 **Idea 止まり**。公開フェーズに入ってから重み付けする。
- [ ] 既存のコストコ価格まとめサイト・ブログと比べた優位点は何か
- [ ] その優位点がトップ画面で伝わっているか
- [ ] 既存サイトが持っていて本サイトに無い機能のうち、P1〜P3 に効くものはどれか
- [ ] 逆に、真似しなくてよい機能はどれか（機能過多の防止）
