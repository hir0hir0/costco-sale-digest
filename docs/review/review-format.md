# 監査レポート様式（監査レーン共通・厳守）

> **レーンの棲み分け**: このファイルは「壊れているものを見つける」監査レーン用。
> 「あると便利な機能」「こう見せた方が分かる」は提案レーンの仕事で、
> 様式は `docs/review/proposal-format.md`、実行は `/propose`。
> **監査中に思いついた提案は Idea として1行メモに留め、提案レーンに送ること。**

各レビュワーは、指摘1件につき以下のブロックを1つ出力する。
**この様式から外れた出力は統合できないため無効とする。**

```
### [深刻度] 一行要約
- **観点**: <自分のエージェント名>
- **対象**: <ファイルパス:行 / 画面名 / データ項目>
- **影響ペルソナ・タスク**: <P1 / T2 のように personas.md のIDで書く>
- **現状**: <事実のみ。実際に読んだコード・データ・画面を根拠として引用する>
- **なぜ問題か**: <ペルソナがタスクを完遂できない具体的な筋道。1〜3文>
- **再現手順**: <手順、または該当コードの読み方>
- **修正案**: <実装可能な粒度。工数感を 小/中/大 で付す>
```

## 深刻度の定義

| 深刻度 | 定義 |
|--------|------|
| **Critical** | 表示されている情報が誤り、または誤解を招く（価格が間違う・告知価格と実売価格が混在する・古いデータが最新に見える）。信頼が壊れる。 |
| **Major** | 情報は正しいが、personas.md のタスクが完遂できない／著しく手間がかかる。 |
| **Minor** | 完遂はできるが快適でない。見た目の粗さ、表記ゆれ。 |
| **Idea** | 現状問題ではないが、あると価値が上がる提案。 |

## 禁止事項

- **推測で書かない。** 実際にファイルを読んだ／画面を見た根拠のない指摘は出さない。根拠が取れない場合は「未確認」と明記する。
- **好みを Major 以上にしない。** 「モダンでない」「色が地味」は Minor か Idea。
- **一般論を書かない。**「UXを改善すべき」のような指摘は無効。必ず対象を特定する。
- **`CLAUDE.md` に既知として記載済みの落とし穴を、新規指摘として再掲しない。**
  ただし「CLAUDE.md に書いてあるのにコードが従っていない」場合は指摘対象（深刻度は1段上げる）。
- **1エージェントあたり最大10件。** 多すぎる指摘は優先順位を殺す。深刻度順に絞って出す。

## 最後に必ず付けるサマリ

```
## サマリ（<エージェント名>）
- Critical: N件 / Major: N件 / Minor: N件 / Idea: N件
- **もし1つだけ直すなら**: <指摘の一行要約>
- **確認できなかった範囲**: <アクセスできなかった/判断保留にした領域>
- **CLAUDE.md に追記すべき知見**: <次のセッションが繰り返さずに済む落とし穴。無ければ「なし」>
```
