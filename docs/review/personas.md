# ペルソナとタスク定義（レビューの物差し）

対象リポジトリ: **costco-sale-digest**

すべてのレビュワーは、このファイルと `CLAUDE.md` を最初に読むこと。
「なんとなく使いにくい」ではなく、**このペルソナがこのタスクを完遂できるか**で評価する。

---

## 確定した前提（2026-08-31 時点）

| 項目 | 確定内容 |
|---|---|
| レシートの範囲 | **自分の購入分のみ**。他人からの提供は受けない |
| 第一の利用者 | **運用者自身（P0）**。一般公開ユーザ向けの作り込みは第2段階 |
| 価格の正典 | **メルマガ・レシートの両方が正規**。どちらかが上位ではない |
| 対象店舗 | メルマガは**全国共通**。店舗軸で分ける必要があるのはレシート側のみ |
| 公開範囲 | **サイトは公開する方針**。ただし出す粒度は下記「公開ポリシー」に従う |

### 2つの価格の意味（両方正規だが、答える問いが違う）

| | メルマガ由来 | レシート由来 |
|---|---|---|
| 何の価格か | 全国共通の**告知価格** | 自分が特定店舗で**実際に払った価格** |
| カバー範囲 | 掲載商品すべて | 自分が買ったものだけ |
| 税・割引の状態 | 表記に依存 | 税込・レジ割引反映後 |
| 商品名 | 日本語の正式名称 | 英字略称・省略形 |
| 店舗差 | 無し（全国） | **あり**（自分の行く店舗の値） |

**両方が正規であることは、同じ系列に並べてよいという意味ではない。**
「過去最安値」「平均価格」を出すときに両者を無条件に混ぜれば、
税の状態も店舗も母集団も違う数値が1つの指標になる。
**混ぜるなら正規化の規則を明示し、混ぜないなら画面で区別する。** ここがレビューの最大の争点。

### 公開ポリシー（legal-risk-reviewer はこれを基準に判定する）

| 区分 | 扱い |
|---|---|
| 公開してよい | 商品名、商品番号、メルマガ価格、セール期間、実売価格の**金額** |
| 粒度を落として公開 | 購入日 → **月単位に丸める**／購入店舗 → **出さない**／購入数量 → **出さない** |
| 公開しない | レシート原本（画像・テキスト）、会員番号、レジ・オペレータ番号、支払方法、カード下4桁 |
| リポジトリ | 生データとレシート原本は `.gitignore`。**public にするなら Git履歴も確認してから** |

> 理由: レシート由来データは「いつ・どこで・何を買ったか」の行動記録である。
> 価格情報として有用なのは**金額**だけで、日付の粒度と店舗は無くても価値が落ちない。
> 出さずに済むものは出さない。

## P0. 運用者としての自分（★現時点の主役）
- レシートを取り込む側。取り込みが**正しく終わったか**を毎回確認したい。
- 検算が合わない・商品が名寄せできなかったとき、**それに気づけること**が最優先。
- 過去の取り込みミスを後から直せることも重要。
- 店頭ではスマホで「これ安いんだっけ」を確認する。この用途は P1 と同じ。

## P1. 週1コストコ組（＝店頭での自分。将来の一般ユーザ像でもある）
- 月2〜4回来店。買うものはほぼ固定（食料品中心）。
- 来店直前にスマホで5分だけ見る。PCは開かない。
- 知りたいのは「今週の値引き」と「これは本当に安いのか」。
- 価格の絶対額より **いつもより安いかどうか** を気にする。

## P2. 年数回まとめ買い組
- 半年に1回、大物（家電・日用品ストック・タイヤ等）を狙う。
- 「この商品は年に何回セールになるか」「底値はいくらか」を知りたい。
- 買うタイミングを決めるために **過去1〜2年の価格推移** を見る。

## P3. クーポン最適化組
- メルマガ/クーポンを起点に買うものを決める。
- 「今週のクーポン対象だけ」を一覧したい。
- 割引の種類（即時値引き / クーポン / メンバー限定 / 期間限定）の違いに敏感。

## 評価タスク

**優先度** は現時点（自分用フェーズ）のもの。★＝今回のレビューで必ず見る／☆＝公開フェーズで見る。

| ID | 優先 | ペルソナ | タスク | 合格条件の目安 |
|----|:--:|---------|--------|---------------|
| T10 | ★ | P0 | 直近のレシート取り込みが正しく終わったか確認する | 検算結果・名寄せ失敗件数が見える |
| T11 | ★ | P0 | 名寄せに失敗した商品を後から手当てする | 未紐付けリストがあり、手で直せる |

| T9 | ★ | 全員 | ある価格が**告知価格か実売価格か**を判別する | 画面上でソースが区別されている |
| T7 | ★ | 全員 | 内容量が変わった商品を、値上げとして認識できる | 単位価格併記、または内容量変更の明示 |
| T3 | ★ | P1 | スマホ縦持ち・片手で T1→T2 を行う | 横スクロール発生なし、拡大なしで読める |
| T1 | ★ | P1 | 今週の値引き商品を一覧する | トップから0〜1クリック |

| T6 | ☆ | P3 | 今週のクーポン対象だけに絞り込む | 割引種別でフィルタできる |
| T8 | ☆ | 全員 | 掲載データの鮮度と**出所**を知る | 最終更新日時＋メルマガ配信日／購入月が分かる |

## 明示的に「やらない」こと（過剰指摘の防止）
- 会員登録・ログイン機能は想定しない（公開閲覧のみ）
- 在庫情報・店舗別在庫は扱わない
- 価格の予測・推奨は行わない（事実の提示に留める）
- レシートの家計簿的な集計（支出管理）は範囲外
- 一般ユーザ向けの案内・オンボーディング・デザインの作り込みは**第2段階**。
  現時点で「初見の人に不親切」だけを理由にした Major 以上の指摘は出さない（Idea に落とす）
- 店舗別の価格比較機能は不要（レシートは自分の行く店舗のみ）

> 上記が実態と違う場合は、このファイルを先に直すこと。
> **物差しが間違ったままのレビューは、全部やり直しになる。**
